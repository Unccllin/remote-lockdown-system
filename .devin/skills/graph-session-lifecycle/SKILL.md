# Skill: Graph Session Lifecycle

## When to use this skill

- **At session start** — before any work, to orient yourself in the graph and retrieve memory.
- **Before writing code** — Rule Zero must be complete before any file is edited.
- **At session end** — to append the trace block, regenerate current-state.md, and capture memory.
- **When you are unsure what phase or debt item to work on** — the lifecycle tells you the only allowed path.

## The mandatory lifecycle (no shortcuts)

```
SESSION-START -> RULE-ZERO -> IMPLEMENT -> VERIFY -> ARTIFACT -> CLOSE-DEBT
                                                                    |
                                                                    v
                                                              SESSION-START (next session)
```

Every agent session must traverse these six nodes in order. The graph spec
(`.devin/graph/GRAPH-SPEC.yaml`) defines entry and exit conditions for each
node. `graph_assert.py` enforces the invariants. Skipping a node is a
graph violation.

## Step 1: SESSION-START

**Goal**: Orient yourself. Understand what work exists and what state the
project is in.

Read these files in order:

1. `.devin/graph/current-state.md` — **read this FIRST**. It is a generated
   artifact (~100 lines) containing the latest session status, convergence
   table (phases / debt / enforcement paths), open debt items, and the next
   session opening sentence. Do NOT edit it by hand — it is regenerated by
   `make gen-state`.
2. `.devin/graph/GRAPH-SPEC.yaml` — all nodes, edges, invariants, phase
   definitions, enforcement path statuses, and debt items. Locate the
   current node and identify what work is next.
3. `docs/adr/DEBT-LEDGER.md` — open debt items and their close criteria.
   If all items are CLOSED, the remaining work is enforcement path
   hardware verification (see convergence table in current-state.md).
4. Retrieve memory:
   ```bash
   python3 scripts/memory.py retrieve --query "keywords from user request"
   ```
   Acknowledge loaded memories in your first response. Working without
   memory is working blind.

**Completion criteria**:
- current-state.md read and understood
- GRAPH-SPEC.yaml read — current node located
- DEBT-LEDGER.md read — open items identified (or confirmed none)
- Memory retrieved and acknowledged
- Session objective stated in one sentence

## Step 2: RULE-ZERO (GATE — read before you code)

**Goal**: Understand the work item deeply before touching any source file.
Code written before Rule Zero is complete will be wrong in ways that are
hard to find later. This is not optional (enforced by invariant I5).

1. Read the relevant skill file(s) in `.devin/skills/`:
   - For phase work: `.devin/skills/phase-N-*/SKILL.md`
   - For hardware testing: `.devin/skills/hw-test-harness-v2/SKILL.md`
   - For environment checks: `.devin/skills/verify-environment/SKILL.md`
   - For navigation help: `.devin/skills/codebase-navigation/SKILL.md`
   - For memory system: `.devin/skills/memory/SKILL.md`
2. Read the source code that will be changed. Open every file you plan to
   edit and understand its current state.
3. Read any ADRs in `docs/adr/` related to the work.
4. Log your understanding to `.devin/graph/trace.md` with `**Read**:` and
   `**Finding**:` lines.
5. Only then open any source file for editing.

**Completion criteria**:
- Relevant skill file(s) read
- Source code to be changed read
- ADRs related to the work read (if any exist)
- Understanding logged to trace.md (with `**Read**:` and `**Finding**:` lines)
- Implementation gaps identified (if any)

## Step 3: IMPLEMENT

**Goal**: Write the code changes. Only after RULE-ZERO is complete.

- Follow existing conventions (see AGENTS.md — server is CommonJS, dashboard
  is ESM, agent Python is ruff-governed).
- Do not duplicate build logic in the Makefile — delegate to `scripts/`.
- Agent Python uses inline `# D-XXX:` comments to trace code to debt ledger
  entries. Match this convention when working on debt items.
- Every line of the diff must be accountable.

**Completion criteria**:
- Code changes written
- Diff visible (every line accountable)

## Step 4: VERIFY

**Goal**: Run the verification suite. A passing test is NOT a close. A
description of what code does is NOT a close. A printed log from actual
execution IS a close.

Run the relevant verification nodes from GRAPH-SPEC.yaml:

```bash
# All tests (unified runner)
export PATH="/home/cllin/.local/node/bin:$PATH"
npm test

# Per-component
cd server    && npm test                    # 368 Jest tests
cd agent     && python3 -m pytest tests/ -q # 344+ pytest tests
cd dashboard && npx vitest run              # 41+ Vitest tests

# Lint
cd server    && npx eslint .                # exit 0 = clean
cd dashboard && npx eslint .                # exit 0 = clean
cd agent     && python3 -m ruff check . && python3 -m ruff format --check .

# Build
cd dashboard && npx vite build
cd electron  && node --check main.js preload.js setup-preload.js setup-wizard.js server-starter.js config.js updater.js

# Shell scripts
bash -n scripts/*.sh

# Environment + graph
make verify-env
make graph-check
```

**Completion criteria**:
- Relevant VERIFY nodes pass (V-SERVER, V-AGENT, V-DASHBOARD, etc.)
- Lint clean (eslint exit 0, ruff check + format check exit 0)
- Build succeeds (if applicable)
- `make graph-check` passes (all 7 invariants I1-I7)

## Step 5: ARTIFACT (EVIDENCE)

**Goal**: Capture a run artifact — actual printed output from live
execution proving the code works.

- For verification nodes: the test output (with pass/fail counts).
- For enforcement paths: the decision chain log from the hardware harness.
- "No setup detected" with condition values printed IS an artifact.
- A timeout with no output is NOT an artifact.

Reference the artifact in trace.md so it is discoverable.

**Completion criteria**:
- Run artifact captured (printed output from actual execution)
- Artifact referenced in trace.md

## Step 6: CLOSE-DEBT

**Goal**: Update the debt ledger and trace, then hand off to the next
session. This is the only node that can mark a debt item as CLOSED.

1. If a debt item was closed, update `docs/adr/DEBT-LEDGER.md`:
   - Set status to `CLOSED`
   - Add `commit_ref` (the commit hash)
   - Add `artifact_ref` (the run artifact path or description)
   - Graph invariant I2 enforces: no debt item CLOSED without both.
2. Append a session-end status block to `.devin/graph/trace.md`. The block
   must include:
   - **RULE-ZERO** — Understanding logged before code changes (`**Read**:` and `**Finding**:` lines)
   - **Fog cleared this session** — with source citations
   - **Fog remaining** — genuinely not in source, with files checked listed
   - **Debt items closed** — commit refs + artifacts
   - **Debt items still open**
   - **Blockers named and status**
   - **Next session opening** — one sentence, specific, no ambiguity
   - **Failure attribution** (if any failure occurred) — name which of the
     5 harness layers caused it:
     1. Task specification — requirements were vague or ambiguous
     2. Context provision — implicit conventions not written down
     3. Execution environment — incomplete setup, missing dependencies
     4. Verification feedback — no tests, no lint, or verification not communicated
     5. State management — cross-session state loss, no progress tracking
3. Regenerate current-state.md:
   ```bash
   make gen-state
   ```
   Or use the single-command close-session tool:
   ```bash
   python3 scripts/graph_session.py close-session --block-file /tmp/session-block.md
   ```
   This appends the block to trace.md AND regenerates current-state.md in
   one step. It also auto-runs memory consolidate (every 5 sessions) and
   decay (every 10 sessions) based on raw session count.
4. Capture memory:
   ```bash
   python3 scripts/memory.py capture \
     --task "what was asked" \
     --learnings "- learning 1" \
     --mistakes "- mistake: correction" \
     --files "- path/to/file"
   ```
   A session without a capture is a lost session. File references are
   mandatory.

**Completion criteria**:
- DEBT-LEDGER.md updated (if a debt item was closed) with commit_ref + artifact_ref
- trace.md updated with session-end status block (all required subsections)
- current-state.md regenerated via `make gen-state` or `close-session`
- Memory captured via `memory.py capture`
- Next session opening stated in one sentence

## Graph invariants (enforced by graph_assert.py)

| ID | Rule | Description |
|----|------|-------------|
| I1 | phase_deps_must_be_complete | No phase runs before its dependencies are COMPLETE |
| I2 | debt_close_requires_evidence | No debt item CLOSED without commit_ref + artifact_ref |
| I3 | hardware_verification_requires_real_artifact | No enforcement path marked verified-on-hardware without real hardware artifact |
| I4 | session_close_requires_trace_update | No session close without trace.md status block update |
| I5 | rule_zero_before_code | No code changes before RULE-ZERO is complete |
| I6 | orchestrator_knows_all_phases | Orchestrator must know about ALL 17 phases (resolved) |
| I7 | complete_phases_have_artifacts | Every COMPLETE phase has non-empty artifact reference (resolved) |

Run `make graph-check` to verify all invariants pass.

## Session lifecycle tooling

| Command | Purpose |
|---------|---------|
| `make gen-state` | Regenerate current-state.md from trace.md + graph spec |
| `make archive-trace` | Rotate old sessions from trace.md to archive files (when >3000 lines, keeps latest 5) |
| `make graph-check` | Run graph_assert.py — all 7 invariants |
| `make graph-status` | Print convergence report (phases, debt, enforcement gaps) |
| `make clean-state` | Run 5-condition clean state checklist |
| `python3 scripts/graph_session.py close-session --block-file <file>` | Append session block + regenerate current-state.md in one step |
| `python3 scripts/graph_session.py generate-current-state` | Regenerate current-state.md only |
| `python3 scripts/graph_session.py archive-trace --threshold 3000 --keep 5` | Archive old sessions |

## Key files

| File | Purpose |
|------|---------|
| `.devin/graph/GRAPH-SPEC.yaml` | All nodes, edges, invariants, phases, enforcement paths, debt items |
| `.devin/graph/current-state.md` | Generated compact session state (read FIRST at session start) |
| `.devin/graph/trace.md` | Full session history (append session-end blocks here) |
| `.devin/graph/trace-archive-*.md` | Rotated old sessions |
| `docs/adr/DEBT-LEDGER.md` | Debt items with close criteria, status, commit/artifact refs |
| `docs/adr/GRAPH-SPEC.md` | Human-readable ADR for the graph |
| `scripts/graph_session.py` | Session lifecycle tool (generate-current-state, archive-trace, close-session) |
| `.devin/graph/graph_assert.py` | Invariant assertion engine (run via `make graph-check`) |
