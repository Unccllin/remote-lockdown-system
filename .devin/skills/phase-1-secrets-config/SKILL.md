# Phase 1 — Secrets & Configuration Management

## Context

The system requires several cryptographic secrets for production:
- `JWT_SECRET` — signs admin auth tokens
- `AGENT_SHARED_KEY` — legacy pre-shared key for agent auth
- `AGENT_KEY_PEPPER` — peppers per-device API keys before hashing
- `FIELD_ENCRYPTION_KEY` — encrypts sensitive DB fields (device names, etc.)
- `LOCATION_FIELD_KEY` — encrypts location data at rest
- Recovery RSA key pair — for offline agent recovery

## Current State

- `scripts/generate-secrets.sh` generates all 4 Docker secrets + prints env var equivalents
  - `--output <dir>` (default: `./secrets/`), `--dry-run`, `--stdout`, `--force` (overwrite)
  - Validates each secret meets minimum entropy requirements
  - Prints summary of generated files
- `scripts/generate-recovery-keys.sh` generates 4096-bit RSA key pair
  - `--output <dir>` (default: `./keys/`)
  - Outputs `recovery_master.key` (private, chmod 600) and `recovery_master.pub` (public)
  - Prints deployment instructions
  - `--force` to overwrite
- `scripts/validate-env.sh` validates environment variables
  - `--check-required`, `--check-strength`, `--env-file <path>`, `--production` (strict), `--json`
  - Exit 0 if valid, 1 if missing vars, 2 if weak secrets
- `server/.env.example` documents all vars (58 lines)
- `.env.prod.example` documents production vars (46 lines)
- `docker-compose.yml` references `./secrets/*.txt` files (generated by generate-secrets.sh)
- `agent/config.ini.example` documents agent config
- `server/src/config/env.js` loads env vars via dotenv (DATABASE_URL or DB_* vars, JWT_*, AGENT_*, FIELD_*, CORS_ORIGIN, NODE_ENV, PORT)
- `server/src/db/fieldCrypto.js` uses AES-256-GCM with the `FIELD_ENCRYPTION_KEY` (32-byte base64)

### Secret Requirements
| Secret | Min Length | Format | Source |
|--------|-----------|--------|--------|
| JWT_SECRET | 32 bytes | hex (64 chars) | `openssl rand -hex 32` |
| AGENT_SHARED_KEY | 32 bytes | hex | `openssl rand -hex 32` |
| AGENT_KEY_PEPPER | 32 bytes | hex | `openssl rand -hex 32` |
| FIELD_ENCRYPTION_KEY | 32 bytes | base64 | AES-256 key |
| LOCATION_FIELD_KEY | 32 bytes | base64 | AES-256 key |
| Recovery RSA | 4096 bits | PEM | `openssl genrsa` |

### Recovery Key Flow
1. Admin generates RSA key pair: private key kept offline, public key distributed to agents
2. Agent encrypts its Fernet key with the RSA public key and stores the wrapped key locally
3. If agent can't reach server, `agent/offline_recovery.py` (167 lines) decrypts the wrapped key using the RSA private key
4. Requires `recovery_master.pub` on device

## Gotchas

- If `FIELD_ENCRYPTION_KEY` changes, existing encrypted data becomes undecryptable — rotation requires re-encrypting all DB data (separate feature, not in this phase)
- Recovery keys are managed separately from app secrets — public key distributed to all devices, private key kept in a safe/HSM
- `docker-compose.yml` mounts secrets as files under `/run/secrets/`; server reads via `process.env.DOCKER_SECRET_PATH` or falls back to env vars
