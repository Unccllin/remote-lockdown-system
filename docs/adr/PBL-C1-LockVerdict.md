## 1. Encoding

A LockVerdict is a **COSE_Sign1** structure (RFC 8152 §4.2). COSE_Sign1
wraps a CBOR-encoded payload with a signature and a protected header
containing the algorithm and key identifier.

```
COSE_Sign1 = [
    protected: bstr .cbor {1: alg_id, 4: kid},
    unprotected: {},
    payload: bstr .cbor LockVerdictPayload,
    signature: bstr
]
```

### 1.1 Protected header

| Label | Name | Value | Notes |
|-------|------|-------|-------|
| 1 | alg | -8 (Ed25519) | EdDSA with Ed25519. If HSM lacks Ed25519, fallback alg -7 (ES256, ECDSA P-256 SHA-256). The alg in use is identified by `kid` → cert in C4. |
| 4 | kid | bstr (32 bytes) | SHA-256 of the signing certificate's public key. PBL resolves `kid` → cert via the `lock_service_cert_pin` field in the policy blob (C4 §2.8). |

No unprotected header parameters are used. All critical metadata is in the
protected header so it is covered by the signature.

### 1.2 Signature

The signature is computed over the **Sig_structure** (RFC 8152 §4.2):

```
Sig_structure = [
    "Signature1",
    protected: bstr,          // the protected header from above
    external_aad: bstr'',     // empty — no external AAD
    payload: bstr             // the CBOR-encoded LockVerdictPayload
]
```

PBL reconstructs this structure exactly and verifies with the public key
from the pinned cert. **No other verification path exists** — PBL does not
trust the platform TLS store for verdict verification (only for the TLS
transport layer, which is C3's concern).

## 2. Payload (LockVerdictPayload)

CBOR map, canonical encoding (RFC 8949 §3.1.1, shortest keys first by
integer value):

| Key | Name | CBOR type | Size | Required | Notes |
|-----|------|-----------|------|----------|-------|
| 1 | version | uint | 1 byte | yes | Wire format version. This spec = `1`. PBL rejects unknown versions. |
| 2 | device_id | bstr | 32 bytes | yes | SHA-256 of the AK (Attestation Key) public Area. Not the EK — the AK is the identity established at enrolment (see C1 §4). |
| 3 | nonce | bstr | 32 bytes | yes | Echo of the client-supplied nonce from the verdict request (C3 §3). Generated by PBL via EFI_RNG_PROTOCOL (fallback TPM2_GetRandom). Never timestamp-derived, never MAC-derived. |
| 4 | verdict | uint | 1 byte | yes | `0` = UNLOCKED, `1` = LOCKED, `2` = WIPE_PENDING. No other values valid. |
| 5 | policy_version | uint | ≤ 5 bytes | yes | The policy version this verdict was evaluated against. Must match the policy version PBL has (or PBL fetches the matching policy via C4). |
| 6 | issued_at | uint | 5 bytes | yes | Unix timestamp (seconds since 1970-01-01 UTC). 32-bit unsigned, expires 2106. |
| 7 | grace_until | uint | 5 bytes | yes | Unix timestamp. After this, the cached verdict is stale and PBL enters denied-boot-with-local-unlock (never brick — see PBL plan §0.2). |
| 8 | reason | tstr | ≤ 128 chars | yes | Human-readable reason code for operators. One of: `"reported_stolen"`, `"admin_lock"`, `"recovered"`, `"policy_violation"`, `"enrolment"`. PBL does not act on reason; it is for the lock screen display and audit log. |
| 9 | challenge_seed | bstr | 16 bytes | no | Present only when `verdict=LOCKED` and an offline override challenge is available (REQ-14). Seeds the challenge displayed on the lock screen. Absent → no offline override available for this verdict. |

### 2.1 CBOR diagnostic example

```
{
  1: 1,                                    // version
  2: h'A1B2C3...32bytes...',               // device_id
  3: h'D4E5F6...32bytes...',               // nonce
  4: 1,                                    // verdict: LOCKED
  5: 7,                                    // policy_version
  6: 1725555200,                           // issued_at
  7: 1726160000,                           // grace_until (~7 days)
  8: "reported_stolen",                    // reason
  9: h'00112233445566778899AABBCCDDEEFF'   // challenge_seed
}
```

### 2.2 Size budget

The full COSE_Sign1 (header + payload + signature) MUST be ≤ 512 bytes.
This fits comfortably in a single UEFI HTTP response body and a single TPM
NV index write (C2 §2.3). PBL rejects any verdict body > 4 KiB (DoS guard).

## 3. Verdict lifecycle and validity

```
Server issues verdict (issued_at = T0)
        │
        ▼
PBL receives via C3 (online path)
        │  verify COSE sig + nonce echo + device_id match
        │  check: issued_at ≤ now < grace_until
        ▼
VALID → cache in TPM NV (C2 §2.3), act on verdict
        │
        │  [server unreachable on next boot]
        ▼
PBL reads cached verdict from TPM NV
        │  check: now < grace_until (from cached verdict)
        ▼
now < grace_until  → honour cached verdict (fail-open on availability)
now ≥ grace_until  → denied-boot-with-local-unlock (NOT a brick)
                     display lock screen, offer REQ-14 override,
                     on failure → ResetSystem(EfiResetShutdown)
```

### 3.1 Validity window defaults

| Parameter | Default | Configurable via |
|-----------|---------|-------------------|
| Verdict freshness (online) | issued_at within 15 min of request | C4 policy blob `verdict_freshness_seconds` |
| Grace period (offline cache) | 7 days | C4 policy blob `grace_period_seconds` |
| WIPE_PENDING validity | 24 hours to execute | C4 policy blob `wipe_deadline_seconds` |

### 3.2 Replay resistance

A verdict is replay-resistant because:
1. **nonce** (key 3) must echo the client's random 32-byte nonce. A replayed
   verdict from a different session has a different nonce → rejected.
2. **device_id** (key 2) binds the verdict to this machine's AK. A verdict
   stolen from another device has the wrong device_id → rejected.
3. **grace_until** (key 7) bounds the replay window. After grace expires,
   the cached verdict is stale regardless of signature validity.

Agent E's negative test REQ-13 covers: replay a stale verdict, replay
another device's verdict, present a verdict with a mismatched nonce.

## 4. Device identity (enrolment binding)

`device_id` is the SHA-256 of the AK (Attestation Key) public Area, not the
EK. The enrolment flow (Agent C `POST /v1/enroll`):

1. Agent D provisions an AK on the device TPM (TPM2_Create, endorsement
   hierarchy, `TPM2_PolicyAuthorize` for future updates).
2. Agent D extracts the AK public Area and computes `device_id = SHA-256(AK_public_area)`.
3. Agent C verifies the AK belongs to the TPM via `TPM2_ActivateCredential`
   (the EK cert is verified against the TPM vendor's EK CA chain at this
   step).
4. Agent C stores `device_id` → {EK cert, AK public, SMBIOS serial, asset
   tag} in the device store. SMBIOS serial/asset tag are metadata for
   humans, never authenticators.

All future verdicts are addressed to `device_id`. PBL computes its own
`device_id` from the AK public Area at boot and rejects any verdict whose
`device_id` does not match.

## 5. Signing key management

- Signing key lives in HSM/KMS (cloud KMS acceptable per charter §6).
- Short-lived signing certs (90 days) chained to a long-lived root held
  offline.
- The signing cert's public key SHA-256 is the `kid` in the COSE protected
  header.
- PBL resolves `kid` → cert via `lock_service_cert_pin` in C4. The cert
  chain is validated up to the root pinned in C4. PBL does **not** use the
  platform's TlsCaCertificate store for verdict verification.
- Key rotation: a new signing cert is published via a policy blob update
  (C4 version bump). Old certs remain in C4's `lock_service_cert_pin_history`
  for the overlap period so cached verdicts signed by the old key remain
  verifiable until their grace expires.

|--------|------|------|----------|-------|
| POST | `/v1/verdict` | `{device_id, nonce, platform_state_digest, policy_version}` | COSE_Sign1 LockVerdict (binary) | Content-Type: application/cose. |

are out of scope for this contract — they are Agent C's internal concern.

## 7. What PBL checks on receiving a verdict (Agent A implementation order)

1. COSE_Sign1 structural parse (CBOR well-formed, required keys present).
2. `kid` lookup in C4 `lock_service_cert_pin` → cert. Reject if unknown kid.
3. Signature verification over Sig_structure.
4. `version == 1` (reject unknown).
5. `device_id == SHA-256(self AK public Area)` (reject mismatch).
6. `nonce == self nonce` (reject mismatch — replay).
7. `policy_version >= self NV counter` (REQ-11 anti-rollback; reject older).
8. `issued_at <= now < grace_until` (reject stale or future-dated).
9. If all pass: cache verdict in TPM NV (C2 §2.3), extend PCR 12/13 (C2 §4),
   act on `verdict`.

Steps 1–8 are **verification only** — no side effects. Step 9 is the only
state-mutating step. This ordering ensures a malformed verdict cannot
corrupt TPM state.
