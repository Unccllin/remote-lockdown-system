## MOLE has a working TPM — the failure is in code
```
Get-Tpm: TpmPresent True, TpmReady True, TpmEnabled True, TpmActivated True
         Win32_Tpm: SpecVersion 2.0, ManufacturerIdTxt IFX (Infineon)

defect 1 (fatal, every check-in):
  the generated PowerShell referenced [System.Security.Cryptography.CngKeyFlags]
  reproduces: 'Unable to find type [System.Security.Cryptography.CngKeyFlags]'
  that type does not exist on Windows PowerShell 5.1 / .NET Framework, so the script threw
  before any TPM call.

defect 2 (why nobody saw it):
  the script writes 'ERROR: <reason>' to STDOUT and returns non-zero; the caller logged
  result.stderr.strip(), which is empty -> the log line read 'TPM key creation failed: '
  with nothing after it, on every check-in, for every device.

defect 3 (the approach itself):
  with the enum line removed, CngKey.Create against 'Microsoft Platform Crypto Provider'
  still fails: 'The requested operation is not supported.' (verified on MOLE)
  the supported path works: New-SelfSignedCertificate -Provider 'Microsoft Platform Crypto
  Provider' -KeyAlgorithm RSA -KeyLength 2048 -CertStoreLocation Cert:\LocalMachine\My
  -> CREATED F4BB9916…C30C18, HasPrivateKey True
  (that is what the module's own docstring says it does; the code did not)
```
