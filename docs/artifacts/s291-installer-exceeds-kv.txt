--- [4] consequences, stated plainly ---
  binary:installer cannot be refreshed on this platform at current payload sizes. It remains the
  2026-11-12 wrapper, and because the wrapper embeds the agent it still installs the old build.
  The three keys that could be refreshed were: binary:agent, binary:agent-installer,
  binary:lockscreen (all verified by download in S290).

  Three ways out, none of which is a tool call:
    a. R2 binding: put the installer in a bucket and serve it from the Worker (no KV size limit).
       Needs a Worker route + wrangler.toml binding + a bucket.
    b. One binary: fold installer.py's enrol/install modes into lockdown-agent.exe, so the wrapper
       embeds ~17 MB instead of 33 MB. A code consolidation, and the largest change of the three.
    c. Host it elsewhere (GitHub release or the self-hosted server) and point the dashboard there.
