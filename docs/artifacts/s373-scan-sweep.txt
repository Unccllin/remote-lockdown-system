## Deliberately NOT fixed, with the reason

**46 `ctypes`/`winreg` findings in `agent/lock_screen.py`.** Left as baseline on purpose:
- This is the class `AGENTS.md` already documents as noise from analysing Windows-only APIs on Linux.
- The file was not otherwise touched; rule 1 says a finding in a file you did not change is baseline.
- Three bulk-edit attempts during this session each introduced a defect a gate caught (a regex import
  insertion produced `FileText,, KeyRound`; an offset replacement broke `worker.ts`'s syntax; a shim name
  in `lock_screen.py` did not match its 39 replacements and produced 44 ruff errors). All three were caught
  by `vite build` / `tsc` / ruff within seconds, and all three were reverted.
- There is no runtime benefit: the paths are gated by `_is_windows()` and cannot execute here.

**17 `unchecked-throwing-call-python` in three firmware operator scripts** (`prepare-live-test.py`,
`gen-policy-rot.py`, `gen-bcd-hive.py`): they are one-shot operator tools that *should* abort on a missing
input — `AGENTS.md` rule 4 protects exactly this behaviour.

## Why the headline count is not a regression measure

A workspace scan is a 300-second budget that stops early and covers a different subset each run: one sweep
reported 55 findings over 191 files, the next 94 over 245 files, having reached `lock_screen.py` for the
first time. Findings were therefore verified file by file (`lens_diagnostics source=lsp` on each touched
file, all now 0) rather than by comparing two totals.
