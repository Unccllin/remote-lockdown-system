--- [4] make full-verify does not include Playwright, and Playwright was red ---
  The chain runs test-e2e (scripts/run-e2e.sh --agent-integration) but not test-e2e-dashboard.
  Running it: 7 failed, 4 passed. All seven were auth-dependent; the login page rendered, the
  invalid-credential path worked, so the backend was up and the API answered.

  FIRST CONCLUSION WAS WRONG. I reported "a genuine red, not a flake". Then:
    ps -o pid,lstart -p 665976,665992 ->
      665976  npm exec vite --port 5173 --strictPort     started Wed Nov 18 14:29  (= S303)
      665992  node .../vite --port 5173 --strictPort
  A Vite dev server S303 had left running for a day was still on 5173. `playwright.config.js` had
  `reuseExistingServer: !process.env.CI`, so Playwright REUSED it instead of starting a server
  bound to this run's E2E_BACKEND_PORT=3101. That server's `/api` proxy was resolved when it
  started (no E2E_BACKEND_PORT -> 3001, which on this box belongs to another project), so the
  browser's login POST went to a foreign backend while the fixture's own axios login went to 3101
  — which is exactly why bootBackend() did not throw "E2E bootstrap: login failed" and why the
  failures surfaced as "element(s) not found" on the device pages.
  The pre-S304 worktree run I launched to attribute the failure was therefore worthless (it reused
  the same wrong server) and was killed rather than counted.

  After killing the stale server, the same suite on the same commit: 11 passed (15.4 s). No
  regression; the code was never broken.

--- [5] the harness defect that caused it, and the fix ---
  dashboard/playwright.config.js: `reuseExistingServer: !process.env.CI`
    -> `reuseExistingServer: process.env.PLAYWRIGHT_REUSE_DEV_SERVER === '1'`
  with the date, the mechanism and the opt-in named in the comment, so the next person reads why
  rather than re-learning it.

  Proof it now fails loudly instead of testing the wrong app: with a dummy listener on 5173,
    npx playwright test e2e/auth.spec.js --grep "login page renders"
    Error: http://localhost:5173 is already used, make sure that nothing is running on the
           port/url or set reuseExistingServer:true in config.webServer.        exit 1, ~1 s
  And the suite still passes with the port free: 11 passed (16.2 s), no listeners left behind.
