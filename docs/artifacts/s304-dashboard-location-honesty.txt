=== S304: dashboard location honesty + a lint gate that lints no JSX (2026-11-18) ===

Options (a) and a byproduct. Option (a) of docs/artifacts/s303-location-diagnosis.txt §5 is
"UI honesty (no new data)": show source, accuracy and age, and label ip fixes approximate.
It is implemented and gated. Chasing the gate to the end found that the dashboard lint gate
never lints a .jsx file, so the whole UI layer has been unlinted while every surface reported
green.

Measured with the same binary the repo pins (eslint v8.57.1, `.eslintrc.json`, no eslint.config.*):

  $ npx eslint .                              -> files linted: 21   .jsx files linted: 0
                                                 errors: 0                       exit 0
  $ npx eslint src/ tests/ --max-warnings=0   -> files linted: 13   .jsx files linted: 0
                                                 errors: 0                       exit 0
  $ npx eslint . --ext .js,.jsx               -> files linted: 72   errors: 30  warnings: 1

Rules behind the 30: no-unused-vars 22, react/no-unescaped-entities 7, no-undef 1, spread over
16 files (worst: EnrollDevicePage.jsx 4, TopBar.jsx 3, EnrollPage.jsx 3, HealthPage.jsx 3).
eslintrc format cannot declare file extensions; v8 defaults to `.js` unless `--ext` is passed.
So every documented dashboard lint invocation — `Makefile:290`, `.github/workflows/lint.yml:46`
and `:75`, `.github/workflows/release.yml:69`, and the `cd dashboard && npx eslint .` line in
AGENTS.md — lints 0 of the dashboard's .jsx files and exits 0 while 30 errors sit in the tree.

--- [4] is any of it ours? ---
Under `--ext .js,.jsx`, the only finding inside the four changed files is
  tests/MapPage.test.jsx:2  no-unused-vars  'fireEvent' is defined but never used
and that import is byte-identical at HEAD (`git show HEAD:dashboard/tests/MapPage.test.jsx`).
Zero errors are attributable to an added line. Baseline 30 is therefore unchanged by this work;
the correct fix is a separate, mechanical pass: add `--ext`, clear the 22 unused vars and the 7
unescaped entities (both mechanical), and fix the 1 `no-undef` by declaring the vitest globals
for `tests/` — `tests/EnrollDevicePage.test.jsx:42` uses the global `afterEach` (available in
vitest config via `globals: true`) with no eslint env for it, so that one is a config gap and
not a defect. Do not widen this diff to absorb a 30-error cleanup.

--- [5] what this means for the "eslint clean" claims ---
AGENTS.md, the diagnostic-sweep section, and S271/S303's VERIFY lines all cite dashboard eslint
as a passing gate. They are true statements about the command that was run and false statements
about the dashboard's lint state. The server side is unaffected (its files are .js, and jest+
eslint there do lint). This is a Layer-4 (verification feedback) failure: a gate whose green
does not depend on the code it claims to check.
