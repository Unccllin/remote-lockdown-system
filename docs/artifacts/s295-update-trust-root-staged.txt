--- [4] what publishing would and would not change ---
  publishing:  npx wrangler kv key put --binding=LOCKDOWN_KV agent_release --path /tmp/agent-release.json
  effect:      /api/agent/update stops answering "no_release_published" and starts offering
               1.0.0 to devices that poll it.

  It does NOT by itself make updates signature-verified: a device only pins the key if its
  config names update_public_key (a PATH to update_signing.pub, not the PEM text — measured:
  passing the PEM inline yields 'Update public key not found'). So publishing metadata and
  shipping the public key are ONE decision with two halves. Today MOLE reports 'sha256-only'.

  The two halves:
    a. publish agent_release (above)
    b. stage update_signing.pub beside the agent binaries before rebuilding the wrapper
       (agent/dist or STAGE=... for scripts/build-generic-installer.sh), so installed agents
       write update_public_key into config.json and refuse unsigned updates.

--- [5] custody, which is the part that is hard to undo ---
  update_signing.key signs every future release. If it is lost, every pinned device must be
  re-provisioned with a new public key; if it leaks, anyone can sign an "update". Whatever
  happens next, that file should be copied somewhere offline and not left only on this host.
  Nothing has been published, so deleting ~/.lockdown-secrets/ and stopping here leaves the
  fleet exactly as it is today: sha256-only, no updates offered.
