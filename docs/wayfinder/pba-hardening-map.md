# Wayfinder Map: PBA + Boot Hardening

> **Label:** `wayfinder:map`
> **Tracker:** local-markdown (`docs/wayfinder/`)
> **Created:** 2026-08-13
> **Status:** Active

## Destination

Implement pre-boot authentication (PBA) and additional boot hardening for the
remote lockdown system, closing gaps identified by the PBA research
(`RESEARCH-PRE-BOOT-AUTH.md`) and UEFI boot research
(`RESEARCH-WINDOWS-UEFI-BOOT.md`). The end state: the agent can apply a
3-layer defense (BCD/UEFI lockdown + HP Power-On Password + BitLocker TPM+PIN),
the server stores all PBA credentials, the dashboard shows a PBA Recovery panel,
and a recovery runbook exists for rebooted PBA devices.

## Decisions so far

<!-- 11 decisions from grilling Round 1 + Round 2, all accepted by the user -->

- [Q1: PBA activation model](tickets/Q1-pba-activation-model.md) — Opt-in flag (`enable_pba: true`, default false). PBA is explicit per-lockdown, not default.
- [Q2: Sure Start BIOS Setting Protection](tickets/Q2-sure-start-lock-then-seal.md) — "Lock then seal": disable protection → apply lockdown → re-enable protection.
- [Q3: Sure Admin handling](tickets/Q3-sure-admin-report-blocked.md) — Report blocked. No signed payloads yet. If Sure Admin is on, skip BIOS changes + report.
- [Q4: Sure Run](tickets/Q4-sure-run-detect-only.md) — Detect and report only. Don't configure Sure Run (separate hardening feature).
- [Q5: SafeBoot registry entries](tickets/Q5-safeboot-install-time.md) — Install time. Agent always starts in Safe Mode, not just during lockdown.
- [Q6: Phase 1 hardening scope](tickets/Q6-phase-1-always-applied.md) — Always apply Phase 1 hardening on every lockdown (no PBA trade-off).
- [Q7: BitLocker dependency](tickets/Q7-require-bitlocker-enabled.md) — Require BitLocker already enabled for Tier 2 PBA. Agent doesn't enable BitLocker.
- [Q8: BitLocker suspension for BIOS changes](tickets/Q8-suspend-bitlocker-for-bios.md) — Extend D-008 pattern to BIOS changes in hp_uefi_lockdown.py.
- [Q9: Server schema migration](tickets/Q9-extend-bios-passwords-table.md) — Extend `bios_passwords` table with `password_type` enum. Migration `008_pba_credentials.sql`.
- [Q10: Recovery runbook](tickets/Q10-recovery-both-dashboard-and-docs.md) — Both dashboard feature AND documentation. Dashboard shows PBA Recovery panel; docs/ has runbook.
- [Q11: Implementation order](tickets/Q11-merge-phase-4-into-phase-2.md) — Merge Phase 4 (Sure Start/Admin) into Phase 2. 3 phases total: Phase 1 (always-on hardening), Phase 2 (HP PBA + Sure features), Phase 3 (BitLocker PBA).

## Not yet specified

<!-- Fog: decisions we can tell are coming but can't yet pin down -->

- **Hardware verification strategy**: Phase 2 + Phase 3 features (HP Power-On
  Password, BitLocker TPM+PIN, Sure Start lock-then-seal) cannot be verified
  without real HP hardware + real BitLocker. How to structure the test
  strategy — mock-only with hardware runbook, or invest in an Azure VM with
  BitLocker for partial verification? Graduates after Phase 1 is implemented.
- **GPO handling for BitLocker TPM+PIN**: The agent needs to ensure the GPO
  allows TPM+PIN before calling `ProtectKeyWithTPMAndPIN`. Should the agent
  set the GPO via registry, or just verify it and fail if disallowed?
  Graduates when Phase 3 implementation starts.
- **PIN generation strategy**: Should the PIN be generated by the agent, by
  the server, or by the operator? 4-20 digits, or alphanumeric with enhanced
  PIN GPO? Graduates when Phase 3 implementation starts.
- **Network Unlock consideration**: Should the system document BitLocker
  Network Unlock as a recovery path for on-prem fleet devices? Graduates
  after Phase 3.

## Out of scope

<!-- Work ruled beyond the destination -->

- **VeraCrypt integration**: Conflicts with BitLocker + BCD lockdown. Not
  recommended per research. Ruled out.
- **HP CMSL signed payloads for Sure Admin**: Requires SPM key provisioning
  infrastructure that doesn't exist. Future project. Ruled out for this effort.
- **BitLocker Network Unlock implementation**: Requires WDS infrastructure.
  Documented as a recovery path but not implemented. Ruled out.
- **Smart card PBA for OS drive**: Not supported by BitLocker for OS volumes.
  Ruled out.
- **Enabling BitLocker if it's off**: Agent requires BitLocker already on for
  Tier 2 PBA (Q7=A). Enabling BitLocker is a separate infrastructure decision.
  Ruled out.
